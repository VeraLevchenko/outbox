# Задача: подписание исходящих писем из серверной папки при недоступном Kaiten

## Цель

Добавить временный источник писем на подпись — `Z:\Проекты_исходящие`. Эта папка находится рядом с `Z:\Исходящие` на том же ресурсе; для backend это аналог соседних каталогов `/mnt/doc/Проекты_исходящие` и `/mnt/doc/Исходящие`. Каждая вложенная папка представляет одно письмо; файлы в ней соответствуют вложениям карточки Kaiten. После выбора письма пользователь выполняет действующее действие «Зарегистрировать и подписать»; подготовка DOCX, конвертация в PDF, подписание через CryptoPro, сохранение результата и запись в журнал работают по текущему алгоритму. Для серверного режима исходящий номер письма берётся из имени папки.

## Требования

1. При входе в учётную запись предложить выбрать режим работы: **«С КАЙТЕН»** или **«С сервера»**. Выбранный режим использовать для списка писем и всех действий с ним в текущем сеансе. Права пользователя и роли сохраняются.
2. В режиме «С КАЙТЕН» оставить действующий сценарий получения карточек, регистрации, подписания и маршрутизации.
3. В режиме «С сервера» показать папки непосредственно внутри `Z:\Проекты_исходящие` как письма, доступные для выбора. При открытии папки показать все её файлы: основной DOCX для регистрации и остальные вложения. Если DOCX несколько, пользователь должен иметь возможность выбрать основной документ, как сейчас при работе с вложениями карточки.
4. Для папки `2331-10` использовать строку `2331-10` **без изменения** как полный номер письма: подставить её вместо `{{outgoing_no}}` в рабочей копии Word, использовать в сформированном документе и поле `formatted_number` журнала. Числовую часть `2331` записать в существующее поле `outgoing_no`, если оно требуется моделью журнала. В серверном режиме не генерировать следующий номер по правилам Kaiten или журнала.
5. Сохранять обычную цепочку после выбора DOCX: подстановка номера и даты в Word, конвертация в PDF, подпись через CryptoPro, сохранение PDF, подписи и приложений, запись в журнал. Содержимое исходных файлов в `Z:\Проекты_исходящие` не изменять.
6. Серверный режим должен работать при полной недоступности Kaiten: получение списка, чтение файлов, регистрация, сохранение и подпись не должны требовать карточку или запрос к API Kaiten. Действия перемещения карточки и загрузки подписи в Kaiten в этом режиме пропускать. Поле ссылки на карточку в журнале оставлять пустым.
7. Данные, которые текущий сценарий берёт только из карточки Kaiten (например, адресат и исполнитель), должны быть доступны для заполнения перед регистрацией серверного письма. Если обязательных данных нет, показать понятное сообщение и не начинать подписание.
8. Путь к источнику сделать настраиваемым для backend: буква `Z:` относится к сетевому диску на рабочем месте, а серверу может потребоваться путь к смонтированному ресурсу. `Проекты_исходящие` и `Исходящие` — соседние папки; первая содержит исходные проекты, вторая сохраняет подписанные документы.
9. Только после успешного завершения всей цепочки, включая сохранение подписи, файлов и записи журнала, переименовать папку проекта, добавив к её имени ` подписано`: например, `2331-10` → `2331-10 подписано`. Исходящий номер в Word и журнале при этом остаётся `2331-10`. Папки с пометкой `подписано` не показывать в очереди на подпись. При ошибке до завершения цепочки исходное имя папки сохранять; при ошибке переименования сообщить об этом пользователю и не запускать повторную регистрацию уже созданного номера.
10. Не допускать повторной регистрации номера, уже находящегося в журнале. Папки с некорректным для номера названием, без DOCX или с недоступными файлами не должны приводить к частично созданной записи журнала; показывать причину пользователю.

## Критерии приёмки

- При входе пользователь выбирает один из двух режимов. Выбор «С КАЙТЕН» ведёт к прежнему сценарию.
- При недоступном Kaiten в режиме «С сервера» видна папка `2331-10` и её файлы; можно выбрать DOCX и нажать «Зарегистрировать и подписать».
- После успешной подписи в Word и PDF указан `2331-10`, в журнале полный номер — `2331-10`, а сохранённые PDF, подпись и приложения относятся к этому письму.
- После завершения алгоритма исходная папка `Z:\Проекты_исходящие\2331-10` переименована в `Z:\Проекты_исходящие\2331-10 подписано` и больше не предлагается на подпись.
- Повторное подписание того же номера блокируется понятной ошибкой без второй записи в журнале.
- Ошибка чтения папки, отсутствие DOCX и ошибка подписи не создают завершённую запись в журнале и не добавляют к имени папки `подписано`.
